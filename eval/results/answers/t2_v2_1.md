# t2_v2_1

cost_usd: 0.406  turns: 10

`todo.py` now has due dates. `add` accepts `--due YYYY-MM-DD`, and `list --overdue` shows only tasks that aren't done and are due before today. Old `todo.json` files still work: I ran the new code on a file made by the original code and it behaved correctly.

**What changed**
- **`add --due`:** the date has to be exactly `YYYY-MM-DD` and a real calendar date. A bad date like `2026-02-30` or `12/01/2026` stops the command with an error and saves nothing.
- **How the date is saved:** a task gets a `due` field only when you give it one. Tasks without a date are saved exactly as before.
- **`list --overdue`:** a task counts as overdue only if it isn't done and its date is strictly before today, so a task due today is not overdue. Tasks with no date are never overdue. Using `--overdue` together with `--all` gives an error, because overdue already means "not done".
- **Display:** `list` and `add` now show `(due YYYY-MM-DD)` after tasks that have a date. Tasks without one look the same as before.
- **Also changed:** I added four tests to `tests/test_todo.py` and one line about due dates to `README.md`.

**What I checked**
- **Tests:** `python -m unittest` passes all 5 tests: the 4 new ones plus the one that was already there. They cover:
  - rejecting 7 kinds of bad date, with nothing saved afterwards
  - the cut-off around today: yesterday is overdue; today and tomorrow are not
  - finished tasks that are past due
  - a mix of old tasks without dates and new tasks with them
- **Real command line, run for real (today is 2026-11-12):**
  1. I used the **original** `todo.py` to make a file with one open task and one finished task, and no dates.
  2. With the new code, `list` and `list --all` showed both tasks as before, and `list --overdue` showed nothing.
  3. I added tasks due yesterday, today and tomorrow, one due back in January, and one with no date. `--overdue` showed only the ones due yesterday and in January.
  4. After I marked the January task done, it dropped out of `--overdue`.
- **The other direction:** the original `todo.py` can still read a file that contains dates. It just ignores them.
- **Errors:** an invalid date, a missing date value, and `--overdue --all` each failed with exit code 2 and a clear message.
- **File format:** I wrote the file through a script, which switched it to Windows (CRLF) line endings. I spotted this in the diff and put the original LF endings back. The final diff contains only the intended changes.

**What I couldn't check**
- **A different "today":** "today" comes from your computer's local date. The command-line checks only ran on 2026-11-12, though the tests also try a fixed date.
- **Hand-edited dates:** if someone edits `todo.json` by hand and leaves a bad `due` value, `list --overdue` will crash on it. Plain `list` won't. I didn't add special handling for this.
- **Earlier issue, not fixed:** new IDs are worked out as "number of tasks + 1". Nothing deletes tasks yet, so this hasn't caused a problem, but if deleting is ever added, IDs could repeat.
