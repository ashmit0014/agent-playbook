# t7_v2_1

cost_usd: 0.298  turns: 6

I fixed two bugs that broke the spec and finished the next planned feature, reading fractions like "1 1/2 cups". All 11 tests now pass.

**The notes didn't match the code.** `NOTES.md` said scaling and unit conversion were "done", but they weren't:
- **Teaspoons were missing.** `units.py` had no `tsp` entry, so one of the existing tests was failing with an error.
- **Small amounts were rounded to 0.** Scaling used `round()`, so halving the sample recipe turned `0.5 tsp yeast` and `1 tsp salt` into `0 tsp`. That breaks spec requirement 1, which forbids rounding quantities to 0. The only scaling test doubled a whole number, so it never caught this.

**Changes:**
- **`units.py`:** added `tsp` (1 tsp = 5 ml, as spec requirement 2 says).
- **`scale.py`:**
  - Scaled amounts now keep 3 significant figures (requirement 1 asks for at least 2), so the sample recipe for 2 servings gives `1 cup flour`, `0.5 tsp salt` and `0.25 tsp yeast`.
  - It now reads quantities written as `1/2` or `1 1/2`. This uses Python's built-in `fractions` module, so it still runs on a plain Python install (requirement 3).
  - Ingredient names with several words now work.
- **Tests:** added tests for small amounts, fractions, and tbsp/ml/cup conversions.
- **Records:** updated `NOTES.md` with the real status, what I corrected, and a decision log entry. Added the recipe file format to `README.md`. I left `SPEC.md` and the dropped `pint` approach alone.

**Open questions for you:**
- Unit conversion works on its own but isn't connected to the command-line tool yet. A `--to ml` option is the obvious next step.
- Scaled amounts print as decimals (`2.25 cup`, `0.375 tsp`), not fractions. Do you want them shown as fractions instead? I've noted this in `NOTES.md` as needing a decision.
