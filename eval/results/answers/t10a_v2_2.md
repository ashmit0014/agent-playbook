I've written the parser for your bank's CSV format, using only Python's standard library (no pandas). Its 10 tests all pass, and it reads all 4 rows of `bank_sample.csv` correctly, signs included.

**What's in the project:**
- **`bank_parser.py`**: `parse_bank_file(path)` returns a list of transactions, each with a booking date, value date, description, amount and balance.
  - Amounts and balances are stored as exact decimals, so `-54.20` stays exactly `-54.20` (no float rounding). Signs are kept as the bank gives them.
  - Descriptions in quotes that contain commas (like `"REFUND, ONLINE SHOP"`) are read correctly.
  - It tolerates the invisible marker some Windows files start with, and skips blank lines.
  - If the header, a date, an amount or the number of fields is wrong, it stops with an error naming the line.
- **`test_bank_parser.py`**: the tests. Run them with `python -m unittest -v`.
- **`NOTES.md`**: the handoff notes for later sessions. They cover the goal, your rules (no pandas; semicolon-separated output; dates as DD.MM.YYYY; negative means spending), what's done and how it was checked, and the next step: the output writer and the command-line entry point.
