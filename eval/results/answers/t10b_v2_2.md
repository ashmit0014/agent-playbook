The converter now writes the file for your budgeting app and runs from the command line. One catch: `NOTES.md` lists several open questions about the app's format that were never answered, so some of the output format is my guess.

**What I checked first:** `NOTES.md` is the only record (there's no git history or issue list). What it says about the files was accurate: the parser exists, and its 10 tests pass on Python 3.14. I didn't need to correct anything.

**What I added:**
- **`writer.py`** writes the budgeting-app file. It meets every requirement in the notes:
  - fields are separated by semicolons;
  - dates are written as `DD.MM.YYYY`;
  - amounts keep the bank's sign (negative = spending), with no rounding;
  - it uses only the standard library (no pandas).
- **`convert.py`** runs the whole conversion: `python convert.py INPUT.csv OUTPUT.csv`. It reads the entire input file before writing anything, so a bad bank file never leaves a half-written output. Errors give the line number. It also refuses to write over the input file.
- **`test_writer.py`** adds 14 tests. All 24 tests pass, and converting `bank_sample.csv` gives:
  ```
  Date;Description;Amount
  01.10.2026;CARD PAYMENT SUPERMARKT 1234;-54.20
  02.10.2026;SALARY OCTOBER;2450.00
  03.10.2026;RENT;-950.00
  05.10.2026;REFUND, ONLINE SHOP;19.99
  ```

**Decisions you need to make:** I treated each open question as a setting rather than a fixed choice. Each default below is a guess, and most can be switched with an option:
- **Columns:** `Date;Description;Amount`, with a header row. You can drop the header with `--no-header`, but changing the columns themselves needs a code change.
- **Which date:** the booking date. Use `--date value` for the value date.
- **Decimal separator:** `.` is the default. Use `--decimal ,` for a comma, which is common with semicolon files, so worth checking.
- **File encoding:** UTF-8 without a BOM. Use `--bom` to add one.
- **Line endings:** Windows-style (`\r\n`). I added this to the open questions.

The quickest way to settle these is a sample file that the budgeting app is known to import correctly. Once they're settled, the defaults are easy to change in `writer.py`.
