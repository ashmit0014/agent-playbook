I've written the parser for your bank's CSV format. It uses only Python's standard library, no pandas, and all 9 of its tests pass. It also reads `bank_sample.csv` correctly.

**What's in the project folder:**
- `bank_parser.py`: the parser. It turns each row of a bank export into a transaction with both dates, the description, the amount and the balance.
  - Amounts keep the bank's sign exactly as given, so spending stays negative, and cents stay exact.
  - Descriptions that contain a comma, like `"REFUND, ONLINE SHOP"`, are read correctly.
  - A file saved with a hidden byte-order mark at the start, or with Windows line endings, still reads fine. Blank lines are skipped.
  - If a file doesn't match the bank format (wrong header, wrong number of columns, a bad date or amount), it stops with an error giving the line number instead of quietly skipping data.
  - For a quick check, `python bank_parser.py <file>` prints what it read.
- `test_bank_parser.py`: the tests. Run them with `python -m unittest -v test_bank_parser`.
- `NOTES.md`: notes for the next session. They cover:
  - the goal
  - your requirements and the reasons for them: semicolon-separated output, dates as DD.MM.YYYY, the sign kept as the bank gives it, and no pandas
  - two choices I made: exact amounts, and stopping on bad data
  - what's done and how it was tested
  - what's still open
  - the next step: the output writer, then the command-line entry point
