# t2_v1_1

cost_usd: 0.311  turns: 6

`add` now accepts an optional `--due YYYY-MM-DD`, and `list --overdue` shows only tasks that aren't done and are due before today. Existing todo.json files without due dates load and list exactly as before. I checked this by running the real command line, and the three unit tests pass.

**What changed**
- **`todo.py`:** a task only gets a `due` field when you give it one, so old entries and tasks added without `--due` are saved unchanged. Bad dates like `2026-13-01` or `20261101` are rejected with an error and nothing is written. `list` now shows `(due …)` after tasks that have a date.
- **Tasks with no due date** never count as overdue, and neither does a task due today.
- **`tests/test_todo.py`:** two new tests. One fixes "today" to 2026-11-12 so the date edge cases don't depend on the clock; the other covers bad dates.
- **`README.md`:** the usage line now includes the new options.

**How I checked it**
- **Old files:** I wrote a todo.json in the old format (no `due` fields) and ran `list`, `list --all` and `list --overdue` on it. All three worked, and `--overdue` correctly printed nothing.
- **Which tasks count as overdue:** I added tasks due in the past, today and the future, one past-due task marked done, and one with no date. `list --overdue` printed only the past-due open task, which is what I wrote down before running it. This used the computer's real date, which is 2026-11-12.
- **Bad dates:** both were rejected with exit code 2, and a byte-for-byte comparison showed the file didn't change.
- **The tests can fail:** I copied the code, deliberately changed "before today" to "on or before today", and the new test failed on that copy.

**Not checked**
- Nobody else reviewed this; all the checks above are my own.
- `--overdue` with `--all` just ignores `--all`, since a task that's done can't be overdue.
- "Today" is the computer's local date, so time zones aren't handled.
- If two people use the same file at once, one can overwrite the other's changes. That was already true before this change.
- Task numbers are still "number of tasks + 1", as before. That's fine because nothing deletes tasks.
