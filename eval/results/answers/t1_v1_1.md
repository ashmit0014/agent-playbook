`summarize()` now skips empty rows instead of crashing, and a file with empty rows gives the same result as the same file without them.

**What I changed**
- `stats.py`: added a small helper, `_is_blank_row`, and `summarize()` now skips any row where every field is empty or only spaces/tabs. That covers `,`, `,,`, ` , `, lines of only spaces, tab-only lines, and rows with more commas than there are columns.
- A row that has some data but is missing the amount (like `b,`) still raises an error. I left that alone on purpose, because skipping it would quietly leave a real record out of the totals.
- `tests/test_stats.py`: added one test for the empty-row case and one confirming that a row with a missing amount still errors.

**What I verified**
- **The crash:** I reproduced it on the original code first: `ValueError: could not convert string to float: ''`.
- **The fix:** I made a test CSV with mixed empty rows and a copy with those rows deleted by hand. `summarize()` now returns the same result for both (`count 3, total 6.0, mean 2.0`).
- **Windows line endings:** a file with `\r\n` line endings and empty rows also works.
- **Tests:** `python -m unittest` passes all 3 tests. I also ran the new tests against the original code and the empty-row test fails there, so it really does detect the bug.

**What I did not verify**
- I haven't tried this on your actual CSV exports, only on files I built to match your description. If your exports have other kinds of empty-looking rows (for example a placeholder like `-` or `N/A`), those would still crash.
- A file with no data rows, or only empty ones, still crashes on the mean (`ZeroDivisionError`). The original code did this too, and I didn't change it because returning 0 or None for an empty file is your call.
- Nobody else has reviewed this. The tests and the dirty-vs-clean comparison are my own checks, although I confirmed they fail on the original code.
